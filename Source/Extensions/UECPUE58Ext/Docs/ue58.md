# `ue58` — Unreal Engine 5.8 feature pack

Start with `ue58_feature_status` to learn which 5.8 plugins are enabled. Most features below are **experimental/beta plugins that are off by default**: enable with `ue58_enable_plugins(plugins=[...])` and tell the user to restart the editor. Never claim a feature worked when its plugin is disabled.

| Feature | Plugin(s) | Tools |
|---|---|---|
| Procedural Vegetation Editor (PVE) | `ProceduralVegetationEditor` (+ PCG, Dataflow, GeometryScripting) | `pve_create_vegetation`, `pve_list_nodes`, `pve_open_editor` + the `pcg` umbrella |
| Control Rig Physics (beta) / Dynamics | `ControlRigPhysics`, `ControlRigDynamics`, `PhysicsControl` | `controlrig_physics_from_physics_asset` + `control_rig` umbrella |
| Direct Mesh Controls (experimental) | `DirectMeshControl` | `dmc_add_component` |
| MetaHuman 5.8 (Mesh to MetaHuman, build, crowds) | `MetaHumanCharacter`, `MetaHumanCrowd`, `MetaHuman` (Animator) | `metahuman_api` |
| Rendering: MegaLights (production), Lumen Lite (beta), Substrate NPR, FSSS, Nanite Foliage | engine | `render_apply_preset`, `render_set_cvars`, `render_get_state` |
| Physics asset iteration | engine | `physics_asset_generate` + `physics` umbrella |
| Game Animation Sample (5.8) | project content from Fab | `gasp_guide`, `gasp_add_character` |
| PCG Python Data Processor (beta) | `PCGPythonInterop` (+ PCG, PythonScriptPlugin) | `pcg_python_processor` + the `pcg` umbrella |
| Batch processing across worker processes | engine (Kismet) | `blueprint_batch_process` |

`ue58_feature_status` also returns `engine.version` (e.g. `5.8.3`) and `engine.known_issues_fixed_in_later_hotfix[]`. When that list is non-empty and a result looks wrong in a listed area (e.g. PCG integer attributes drifting after Spline Sampler on < 5.8.3), tell the user it is an engine bug fixed in that hotfix instead of retrying blindly.

## Procedural Vegetation Editor (PVE)

PVE is a **PCG graph**: `UProceduralVegetation` owns a `UProceduralVegetationGraph : UPCGGraph`, and every PVE node is a `UPCGSettings` subclass named `PV*Settings`. That means the whole `pcg` umbrella works on it.

Workflow:
1. `pve_create_vegetation(name, save_path)` → returns `graph_path`.
2. `pve_list_nodes(filter?)` → node classes with editable properties (use the exact `class` string with `add_pcg_node(graph_path, settings_class=...)`).
3. Canonical chain (top to bottom): `PVSeedGeneratorSettings` (or `PVPresetLoaderSettings` / `PVPlantProfileLoaderSettings` when the user has presets, or `PVExtractFromMeshSettings` / `PVExtractFromImageSettings` to derive a skeleton from an existing mesh or leaf atlas) → one or more growers (`PVGrowerSettings` with sub-settings: `PVGrowerTrunkGrowthSettings`, `PVGrowerBifurcationSettings`, `PVGrowerDirectionalSettings`, `PVGrowerPhototropismSettings`, `PVGrowerGravitySettings`, `PVGrowerPhyllotaxySettings`, `PVGrowerAuxinSettings`, `PVGrowerAgeSenescenceSettings`, `PVGrowerLightSenescenceSettings`, `PVGrowerFoliageSettings`) → shaping (`PVRotateBranchesSettings`, `PVRemoveBranchesSettings`, `PVScaleSettings`, `PVSlopeSettings`, `PVGravitySettings`, `PVSimplifySettings`, `PVBoneReductionSettings`) → interaction (`PVObjectInteractionSettings` for avoidance, `PVCarveSettings`) → foliage (`PVFoliagePaletteSettings` + `PVFoliageDistributorSettings`; grafting via `PVGraftPaletteSettings` + `PVGraftDistributorSettings`) → mesher (`PVMeshBuilderSettings` with `PVMeshBuilderBranchRadiusSettings`, `PVMeshBuilderDisplacementSettings`, `PVMeshBuilderMeshDetailSettings`, `PVMeshBuilderProfileDetailSettings`, `PVMeshBuilderSkeletonShapingSettings`, `PVMeshBuilderMaterialDetailSettings`) → `PVTrunkTextureSetupSettings` (trunk material compositor) → `PVExportSettings`.
4. Configure nodes with `set_pcg_node_property`, wire with `connect_pcg_nodes` (pins are the PCG defaults: `In`/`Out`).
5. Export node (`PVExportSettings.ExportSettings`): `ContentBrowserFolder.Path`, `MeshName`, `ExportMeshType` (`SkeletalMesh` = wind animation via `WindSettings` asset; `StaticMesh` = no wind), `bCreateNaniteFoliage` (default true — needs `render_apply_preset('nanite_foliage')`), `NaniteShapePreservation`, `bCollision` / `CollisionGeneration`, `ReplacePolicy`.
6. Generation and export run inside the PVE editor: `pve_open_editor(asset_path)` and ask the user to Generate → Export. Report the expected output path (`ContentBrowserFolder/MeshName`).

Use `PVPointScatterSettings` (a PCG subgraph) inside a *level* PCG graph to scatter the exported trees; combine with `populate_landscape` / the `pcg` umbrella and the Dynamic Wind settings for skeletal-mesh trees.

## Control Rig Physics & Dynamics (5.8)

Physics rigs are **layered**: they composite on top of existing animation. Units (add with `add_rig_vm_node(unit_struct_path=...)`, pins via `set_rig_pin_value` / `connect_rig_pins`):

- Solver: `/Script/ControlRigPhysics.RigUnit_AddPhysicsSolver` — inputs `Owner` (bone key), `SolverSettings`, `SimulationSpaceSettings`; output `PhysicsSolverComponentKey`.
- Bodies/joints/controls: `RigUnit_AddPhysicsBody` (`Owner`, `Solver`, `Dynamics`, `Collision`, `BodyData` → `PhysicsBodyComponentKey`), `RigUnit_AddPhysicsJoint` (`ParentBodyComponentKey`, `ChildBodyComponentKey`, `JointData`, `DriveData`), `RigUnit_AddPhysicsControl` (`ControlData`, `ControlMultiplier`), `RigUnit_AddPhysicsComponents`.
- From a Physics Asset in one node: `RigUnit_HierarchyInstantiateFromPhysicsAsset` (`PhysicsSolverComponentKey`, `PhysicsAsset`, `bUseAutomaticSolver`, `ConstraintProfileName`, `BonesToUse` (bone mask), `bEnableJoints`, `bEnableDrives`), `RigUnit_HierarchyImportCollisionFromPhysicsAsset`, `RigUnit_HierarchyAutoCalculateCollision`.
- Forces (new in 5.8, animatable over time): `RigUnit_HierarchyAddPhysicsBodyForce` (`PhysicsBodyComponentKey`, `ForceAndTorque`, `Name`) / `RigUnit_HierarchyRemovePhysicsBodyForce`.
- Runtime tweaks: `RigUnit_HierarchySetControl*` (strength, damping ratio, target, multiplier, enabled), `RigUnit_HierarchySetBodySolverSettings`, `RigUnit_HierarchySetCollision`, `RigUnit_HierarchyDisableCollisionBetween`, getters for body transform/velocity.

`controlrig_physics_from_physics_asset(control_rig_path, physics_asset_path)` places solver + instantiate nodes in the Construction event and wires the solver key; then `compile_control_rig`. Modular Control Rig ships physics modules and the Animator Kit has physics utility rigs — prefer those when the user uses modular rigs.

**Control Rig Dynamics** (`ControlRigDynamics`) is the lightweight particle solver for cosmetics (cloth, hair, accessories, ~5x faster): units `RigUnit_HierarchyAddDynamics*` (particles, constraints, cone limits, colliders: box/capsule/plane, confiners, force fields). Same authoring pattern.

## Direct Mesh Controls (DMC)

`UDirectMeshControlComponent : USkeletalMeshComponent`. Controls are represented on mesh regions (polygroups) so the animator click-drags the surface in the viewport/Sequencer. `dmc_add_component(blueprint_path, skeletal_mesh_path)` adds the component; the user then uses the DMC polygroup tool (Skeletal Mesh editor → Direct Mesh Control) to map regions to controls. Co-exists with regular shape controls.

## MetaHuman (5.8)

The editor subsystem `MetaHumanCharacterEditorSubsystem` is BlueprintCallable/Python-friendly. `metahuman_api`:
- `probe` — lists the subsystem methods and struct fields present in this engine (do this first; names below may differ by hotfix).
- `can_build` / `build(character_path, quality=Cinematic|High|Medium|Low, pipeline=Cinematic|Optimized)` — assembles the MetaHuman (`CanBuildMetaHuman` / `BuildMetaHuman` with `MetaHumanCharacterEditorBuildParameters`).
- `export_dna(character_path, output_path)`.
- `conform_body_from_mesh(character_path, mesh_path)` — **Mesh to MetaHuman** body conform: extracts vertices with `GetMeshDataForConforming` and calls `ConformBodyToTarget`. Head/combined conforming uses `ConformToTargetMeshes(character, TargetMeshKey{BodyMesh, HeadMesh, CombinedMesh}, ConformTargetParams)` — use `action='python'` with a script after `probe` shows the exact `ConformTargetParams` fields. Then `CommitFaceState` / `CommitBodyState` and `build`.
- `python(code)` — anything else (`unreal.MetaHumanCharacterEditorSubsystem`), e.g. `ExportGeometry`, `ExportMaterials`, `DuplicateMetaHumanInstance`, rendering quality profiles.

Scaling to many humans: **MetaHuman Crowd** plugin (`MetaHumanCrowd`) — `UMetaHumanCrowdAnimationConfig` data asset, Mass-driven instances with Nanite/ISM LOD transitions; use `mass_entity` + `data` umbrellas to author configs. Animator body capture (experimental) lives in the `MetaHuman` plugin.

## Rendering (5.8)

`render_apply_preset(preset)`:
- `megalights` — production-ready in 5.8 (needs VSM + Nanite): `r.MegaLights.EnableForProject 1`, `r.MegaLights.Allowed 1`. Debug: `r.MegaLights.Debug 1`, Light Finder / ray visualizer.
- `megalights_translucency` — high quality translucency under MegaLights.
- `lumen_lite` — beta irradiance-field GI (`r.Lumen.IrradianceFieldGather 1`), ~2x faster; default on handhelds.
- `substrate`, `substrate_npr` (Toon BSDF + ToonProfile asset, ramp diffuse/specular, X-Rite AxF import available).
- `fsss` — Fog Screen Space Scattering (`r.Fog.ScreenSpaceScattering 1`).
- `nanite_foliage` — required for PVE Nanite foliage exports.
- `hwrt_lumen`.
Project-wide changes edit `DefaultEngine.ini` via `URendererSettings` and usually need a restart / shader recompile — say so.

## Physics assets (fast iteration)

`physics_asset_generate(skeletal_mesh_path, geometry=capsule|sphere|box|convex|multi_convex|tapered_capsule, min_bone_size, create_constraints, body_for_all, ...)` creates or regenerates a Physics Asset from the mesh in one call (`FPhysAssetUtils::CreateFromSkeletalMesh`) and assigns it. Then refine with the `physics` umbrella (`physics_asset_set_capsule/box/sphere`, `physics_asset_set_constraint_limits`, `set_physics_body_properties`, mass scale, physics mode) and re-run with new parameters to iterate. 5.8 Skeletal Mesh editor adds joint locking, morph-target editing (mirror/flip/split/lattice), skin-weight locking and unused-bone removal — those are interactive tools; point the user to them when needed.

## Game Animation Sample (5.8)

`gasp_guide(topic)` returns the asset map and step lists; `gasp_add_character(skeletal_mesh_path, retargeter_path?)` creates the child character (retarget mesh, ABP_SandboxCharacter, RTG tag, hides mannequin, registers the retargeter in `ABP_GenericRetarget.IKRetargeter_Map`). New in the 5.8 sample: Pose Search Interaction Assets (multi-character motion matching), `SandboxCharacter_Mover_Ragdoll` (powered ragdoll + motion-matched get-up), Chooser with Pose Match column + blend spaces in the blend stack, experimental Look-At POI solver in Control Rig, Smart Object bench sitting via State Tree.

## PCG Python Data Processor (5.8)

A PCG node that runs Python with direct access to the incoming PCG data. Enable `PCGPythonInterop` first (`ue58_enable_plugins`, restart). The node runs on the game thread and is **not cached** — use it for logic that is awkward in nodes (custom filtering, external data, lookups), not for millions of points per frame.

`pcg_python_processor(graph_path, script | script_file, inputs?[], outputs?[], pos_x?, pos_y?)` creates the node (or reconfigures `node_index`) and returns the pin labels to wire with `connect_pcg_nodes`. Default pins are `Input` / `Output`; every dynamic pin accepts any data type with multiple connections. `script_file` paths are relative to the project directory.

Script contract — `data_in` is the input collection, `data_out` the one you build:
```python
data_list, _ = data_in.get_typed_inputs_by_pin_label('Input', unreal.PCGPointData)
for data in data_list:
    points = data.get_points()
    kept = [p for p in points if p.transform.translation.z > 100.0]
    out = unreal.PCGPointData()
    out.set_points(kept)
    data_out.add_to_collection(out, 'Output', ['HighGround'])
```
Always emit on an existing output pin label. After wiring, `generate_pcg` on the actor and check the log for Python errors.

## Batch processing (5.8)

`blueprint_batch_process` wraps `unreal.BatchProcessLibrary.run_batch`: it fans one UFunction out over N worker editor processes and returns `{jobs, passed, failed, failures[]}`. It **blocks the editor** until every job finishes — warn the user for large projects and start with `max_jobs` to try it.

1. The function must be a UFunction the workers can load. For Python, declare it in a module under `Content/Python` (e.g. `snapshot_assets.py` with `@unreal.uclass() class SnapshotAsset(unreal.Object)` and `@unreal.ufunction(params=[str]) def snapshot_asset(self, asset_path)`) and import it from `init_unreal.py` so workers register it. Guard any top-level work with `if __name__ == '__main__':` — otherwise each worker re-launches the batch.
2. Call `blueprint_batch_process(function='/Game/Python/snapshot_assets_PY.SnapshotAsset:snapshot_asset', asset_class='Blueprint', path='/Game')`, or pass `arguments=[{"asset_path": "..."}, ...]` explicitly (keys = parameter names).
3. Report `failed` and the per-job `output` tail. Use `num_workers` to cap CPU use (0 = auto by core count).

Good uses: validate/snapshot every Blueprint, bulk property fixes, re-saving assets after an engine upgrade.
